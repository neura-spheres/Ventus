# Ventus 1.0.39 release verification

Built locally on 2026-10-30 from the existing working tree. No source commits or branch pushes were requested or performed. The release tag uses the existing remote commit `b58370221dcced98e9e7711955ac42097cfbfe0a`; automatic GitHub source archives therefore do not reproduce these binaries.

## Build and automated checks

- Cargo package, app configuration, and installer defaults updated to 1.0.39.
- `cargo fmt --check`, `cargo check --locked`, and all 144 Rust tests passed.
- All 15 JavaScript tests passed, including frontend startup timing and disabling the DevTools preview column.
- Chrome inline script syntax passed; all 270 bundled adblocker JSON files parsed.
- `cargo build --release --locked` passed. The executable's Windows FileVersion and ProductVersion both report 1.0.39.
- Inno Setup compiled `Ventus-Setup-1.0.39.exe` successfully. The WebView2 registry ID was corrected against Microsoft's distribution documentation and matches the installed runtime's registry entry.
- ZIP integrity passed, its executable matches the release build, and all 928 adblocker files match the bundle byte for byte. No raw environment files, signing keys, or certificates were packaged.
- RustSec audit with `--no-yanked` reported zero known vulnerabilities, eight maintenance warnings, and two soundness warnings across the full dependency graph. The separate yanked-crate lookup timed out; it is not counted as a successful check. See the dependency refresh report for target-specific warning details.

## Release app smoke checks

The optimized application was launched from the staged distribution folder.

- The About version displays 1.0.39; address bar and settings open/close work.
- HTTPS content renders. An advertising resource request is rejected with `net::ERR_BLOCKED_BY_CLIENT`.
- First-open Inspect selects the fixture's H1; repeated Inspect selects its button. The frontend width matches the dock within one CSS pixel. Picker, panel resize, fullscreen restore, and closing the panel pass.
- A YouTube `movie_player` fullscreen test keeps the viewport at 1536 × 864 after both a corner drag and a direct resize command. Resize handles hide, and the normal resize cursor returns after leaving fullscreen.
- Six cloud settings are emitted into the release build; the running app reports Firebase and Cloudinary configured.
- Firebase's project configuration endpoint returns HTTP 200, with the expected auth domain authorized.
- A Cloudinary request with the configured upload preset and no file returns `Missing required parameter - file`; an invalid-preset control returns `Upload preset not found`. This checks the cloud and preset configuration without creating a remote asset.
- The application was relaunched normally after testing, with no listener on the temporary debugging port.

## Limits

The application and installer are unsigned. A clean-machine installation, real account sign-in/sync, a complete Cloudinary upload, and paid AI-provider calls were not exercised. The installed WebView2 runtime is 156.0.4314.50. DevTools frontend assets require internet access on first load. The available innoextract 1.9 tool supports only installers through Inno Setup 6.0.5 and could not inspect this newer installer, so its failure is not used as an installer integrity result.
